# Full-tree code review — 2026-09-16

Scope: entire repository at the first public push. Effort: high. Private key handling verified safe (never logged, never echoed by viem errors, only passed to `privateKeyToAccount`).

## High

1. `src/mcp/paidTool.ts:71` — Guard checks a different challenge than the one paid. `decodeChallenge` reads `accepts[0]` of the first 402; `wrapFetchWithPayment` re-requests, parses its own 402, and pays the first accept matching `config.network`, not `accepts[0]`. A seller returning `[{84532, "1000"}, {8453, "900000"}]` to a Base buyer with guard 0.10 passes at $0.001 and signs $0.90. Fix: push the cap into `client.setSpendControls` / `registerPolicy` so the checked amount is the signed amount.

2. `package.json:7` — `bin` points to `dist/index.js`; `dist/` is gitignored; no `prepare` script. `npx -y github:vera-agent-dev/x402-tools` (README, `.mcp.json`, `plugin.json`) installs no bin target. Fix: add `prepare: npm run build` (and ship `dist/` in `files` for npm).

3. `src/adapters/apiClient.ts:37` — `entry.path` from the remote catalog goes through `new URL(path, baseUrl)`; an absolute URL replaces the host, redirecting paid calls (args + auto-payment) to an arbitrary origin. Fix: assert resolved origin equals the base origin.

## Medium

4. `src/mcp/server.ts:30` — Catalog never schema-validated (zod is a dependency, unused here). Missing/non-numeric `price_usd` throws at startup instead of falling back to bundled. Descriptions/enums copied verbatim into MCP tool metadata: prompt-injection surface from the seller. Fix: zod schema, length caps, strip control characters, fall back on failure.

5. `src/mcp/catalogLoader.ts:18` — `fetchCatalog` has no timeout and `createServer` awaits it before `connect()`; a stalled seller blocks `initialize`. Fix: `AbortSignal.timeout`, fall back to bundled.

6. `src/mcp/paidTool.ts:95` — Two disagreeing caps: local `X402_MAX_PRICE_USD` vs library default `spendControls` ($1). Forward `maxPriceUsd` into `setSpendControls`.

7. `src/mcp/paidTool.ts:102` — After settlement, `paidRes.json()` / `decodeSettlement` can throw; the paid result and tx hash are lost and a retry pays again. Fix: catch, return raw body + whatever settlement info decoded.

## Low

8. `src/index.ts:9` — `Number(X402_MAX_PRICE_USD)` unvalidated (`''`→0, `'abc'`→NaN, negatives). Fail at startup with a clear message.

9. `.mcp.json:7` — Tracked file with an empty `X402_BUYER_PRIVATE_KEY` slot invites committing a key. Use `${X402_BUYER_PRIVATE_KEY}` env reference or document never to edit it in place.

10. `src/domain/challenge.ts:44` — Decoded header may be `null`/number/string; `parsed.accepts` throws a raw TypeError; `accepts` not checked to be an array.

11. `src/mcp/server.ts:68` — Test gaps: no `createServer` test (live vs bundled, arg coercion), no test for `accepts[0]` on a different network than `X402_NETWORK`, none for post-payment decode failure, none for env parsing. `createPaidFetch` fully mocked, so finding 1 is invisible to the suite.
